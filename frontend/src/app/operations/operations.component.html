Backend security controls (from repository code)

These protections are implemented in the Play application filters — not in this static demo UI. Selecting a simulated scenario above does not enforce roles or change security posture.

  • Authentication: Production path is Shibboleth/HAKA (documented). DevAuthFilter can inject mock X-User-* headers when exam.dev.auth.enabled / DEV_AUTH_ENABLED is true — suitable only for local development, never for this public GitHub Pages demo.
  • Rate limiting: RateLimitFilter — token bucket per IP, default 100 requests / 60 seconds on /api/v1/ paths (configurable).
  • Security headers: SecurityHeadersFilter — HSTS, CSP, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, Permissions-Policy.
  • Correlation IDs: CorrelationIdFilter — reads or generates X-Request-ID, adds it to MDC and response headers.
  • Audit logging: AuditLogFilter — structured access logs for API requests (user, IP, endpoint, status) when enabled.

This page is a portfolio showcase. It is not an official CSC service and not a complete production EXAM installation.
